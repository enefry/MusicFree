# 专辑列表封面闪烁：排查与修复

## 画面证据

- `img_121.jpg`：封面已经显示，副标题只有年份和歌曲数。
- `img_122.jpg`～`img_124.jpg`：三份文件 SHA-1 相同；艺人名补全时，有封面的卡片同时进入加载占位。
- `img_125.jpg`：多数封面恢复，右下角仍在加载。

## 原因

进入专辑列表时创建新的 `LibraryCollectionsViewController`，其 `artistNames` 从空开始。
异步艺人查询完成后调用 `renderSnapshot()`，副标题变化使 diffable data source 重新配置已有单元格。
原来的网格和列表 cell 每次 `configure` 都取消任务、清空图片，再读取本地封面并解码。

`LocalMediaSource.artwork` 返回 `.localFile`，这条路径无需网络，但仍需要文件读取和图片解码。
原专辑列表绕过了 `LibraryArtworkImagePipeline` 的缓存，导致一次文字刷新触发所有可见封面的重复读取和解码。

## 已实现

- `MusicFreeUI/Package.swift` 精确依赖 Kingfisher 8.12.0，许可登记在 `ThirdPartyNotices`。
- `LibraryArtworkImagePipeline` 使用 Kingfisher 管理解码、缩略图处理和图片内存缓存。
  缓存预算保持 64 MiB / 512 项，使用 300 秒内存过期策略；本地原图仍由现有存储管理，不另存一份磁盘图片缓存。
- 缓存键区分来源、封面标识、处理尺寸；保留并发请求合并及缺失/损坏资源的 30 秒重试节流。
- 自定义 `ImageDataProvider` 保留 `ArtworkServing` 接口和 20 MiB 输入上限，在后台读取本地文件或流。
- 新增 `LibraryArtworkBinding`：同步检查内存缓存；同一封面文字更新时保留图片和加载任务；更换封面、删除封面和复用时更新请求身份，阻止旧结果覆盖。
- 专辑网格、专辑列表和艺人列表接入 binding。网格按显示宽度、屏幕 scale 选择缩略图尺寸；尺寸升级期间保留已有图片。
- 原来调用资料库共享 pipeline 的歌曲列表、搜索结果、详情歌曲行等自动使用 Kingfisher 缓存。播放器独立 pipeline 和其他直接解码入口不在本次迁移范围内。
