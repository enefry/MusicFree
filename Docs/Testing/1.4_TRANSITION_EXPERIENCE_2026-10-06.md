# 1.4 播放过渡体验复查（2026-10-06）

基线：`feature/1.4.0_dev`，HEAD `0554d74`。用户反馈本地音乐在播放、暂停、停止、下一曲、切歌时都没有过渡听感。本轮保留现有 UIKit、插件设置、EQ、导入等未提交修改，不提交、不发布。

## 结论与范围

确认并修复了三个控制路径缺陷。已有测试只能证明引擎播放或 handoff 成功，本轮增加从设置和正式播放 Coordinator 驱动真实 AVAudioEngine 的输出能量采样，覆盖用户提到的操作。

本地 mono WAV、1 倍速、明确设置淡入/淡出各 1 秒时，普通播放、暂停、停止、下一曲、选择另一首在修改前已经有可测包络；重新选择当前歌曲缺少淡出，已修复。不能据此认定用户实际歌曲和当前配置下的“所有操作无效果”已经复现或完全解决。尚缺用户当前速度和淡入/淡出时长，用户仅确认了本地音乐。

## 确认的缺陷与修复

1. **重新选择当前歌曲绕过淡出。** `PlaybackCoordinator.prepareAndPlay` 只在 item ID 不同时调用 stop；同一首重新 prepare 会立即拆除原图。现在重新 prepare 已加载曲目也先 stop，并等待有界的软停止。
2. **重缓冲回调截断软淡出。** 用户 pause/stop 会立即置 wantsPlayback=false；随后 starved → ready 回调进入 updateOutput，按用户意图直接暂停 AVAudioEngine，包络没有机会完成。现在软控制任务存活期间保持 render 输出，由包络完成或有界 deadline 终止。专门延迟 PCM 读取，耗尽缓冲后在淡出中恢复，验证输出继续存在。
3. **在线试听停止、关闭、切歌直接 hardStop。** 用户操作现在使用软停止，替换曲目前等待淡出。正式播放接管、关闭服务、中断及旧音频设备移除保持立即停止。用户 close 已清空 session 而淡出尚在运行时，中断仍会停止残留输出。

新增安全诊断仅记录操作、过渡模式、速度、三个时长、graph/running 标志，以及下一首准备失败的稳定诊断码，不记录媒体 URL 或凭据。

## 包络证据

采样通过实际 AVAudioEngine mixer 的离线渲染输出进行，在 iOS Simulator 执行，不是 FakePlaybackEngine 的状态断言。每块 512 帧、48 kHz；比较开头约 107 ms 和接近 1 秒的等长窗口。

- 本地 1 秒淡入的均方能量窗口和约为 `0.00476 → 1.23139`，淡出约为 `1.23656 → 0.005`。
- 修改前重新选择当前曲目测到 `0.00476 → 1.23139`，说明已经直接开始下一次淡入，旧曲未淡出；修改后先得到正常淡出，再得到正常淡入。
- 网络 Range 和顺序流分别覆盖播放、暂停/恢复、停止、关闭、下一首、选择曲目、重新发起试听，1 秒淡入约为 `0.00113 → 0.29354`，淡出约为 `0.29477 → 0.0013`。
- 重缓冲测试反向验证：临时还原旧 updateOutput 判断，同一测试在淡出中检测到 engine 已停止而失败；恢复修复后通过。

测试不会把只存在状态变更或无输出的窗口当成通过。

## 实际体验的剩余边界

默认淡入/淡出是 80/120 毫秒，用于抑制突变；旧配置缺失字段迁移为 0 秒。自动歌曲衔接和单曲淡入淡出为独立设置，gapless 本身不会制造渐变听感。当前变速路径会降级单曲 fade，自动 gapless/crossfade 仍受资源与时序能力限制。没有覆盖用户已经保存的 0 秒选择。

尚未验证用户当前歌曲、实际设备听音、设备路由切换或 Archive。本轮没有声称完成这些验收，也没有声称完成最新 UIKit 界面的端到端播放交互验证。要闭合用户报告，仍需当前速度/时长及实际操作对应的 transition 日志；新日志可区分配置为零、变速降级与实际图控制异常。
