# 1.4 现有能力迁入插件 Runtime

2026-10-03，`feature/1.4.0_dev`。按用户要求，先提交已有工作：`6e60cc1`（实现）、`c2b406f`（开发与验证记录），再实施本次迁移。保留所有原 Provider、原生在线源和引擎 EQ 实现。

## 生产入口

| 能力 | 注册与执行路径 | 兼容行为 |
| --- | --- | --- |
| LRCLIB / Metadata Server 歌词 | 六个数据插件中的 Lyrics factory → Runtime → PluginLyricsProviderAdapter | 原 Provider ID、排序、LRC/offset、本地歌词优先逻辑 |
| MusicKit / MusicBrainz / Metadata Server / Discogs 歌曲信息 | Metadata factory → Runtime → PluginMetadataProviderAdapter | 原 Provider ID、补全记录、用户编辑保护、错误/限流信息、封面；本地时长 probe 留在宿主 |
| DS Audio / Google Drive | NativeOnlineSourceRegistrationProvider → Runtime → 原生 Source factory | 原账户 ID、Keychain 引用、目录/排序/游标、OAuth、一次性验证码、下载进度和 receipt、试听访问 |
| 十段 EQ | EqualizerDSPPlugin → DSP 宿主 → 选定位置 | 原 EQ 设置与预设保留，默认总线混音后；引擎内旧 EQ 在生产实例中旁路，避免重复处理 |

AppContainer 的歌词/歌曲信息数组仅使用插件适配器。原实现文件保留，但生产组合根不再重复注册。CompositeOnlineSourceFactory 优先将已注册 DS Audio / Google Drive 送入 Runtime，原生服务实例在授权操作时才构造；Baidu Pan / Gateway 沿用原来未实现的状态。

原生在线源桥在 Runtime 操作租约内直接返回宿主的完整 DTO，保留原生认证错误，不经通用插件 DTO 的降维转换。每个账户单独配置、加载和撤销；撤销后的迟到下载结果会通过 discardResult 清理其文件。

## 设置与授权

描述符 `dataProviderID` 与插件 ID 分开。已有服务 ID 保留为 `lrclib`、`metadataServer`、`musicKit`、`musicBrainz`、`discogs`，避免出现第二套 Provider 设置和记录。

SettingsCoordinator 在首次读取、保存和重置时调用 PluginServing.adaptingSettings；迁移后写入同一份 UserDefaults 设置。读取与写入按顺序执行，保存完成前同步 Runtime，再发布变化。旧设置页接收标准化后的插件配置并更新排队编辑，避免连续改参数或重置时恢复旧值。

- 无既有插件偏好时，迁移旧 Provider 开关、明确的服务同意、原生源披露与 EQ 参数；仅填入加载许可，不发起服务请求。
- 已有插件偏好优先，重启不会恢复插件禁用、加载阻止或撤权；旧编辑器的明确开关/授权变化仍会同步到相应插件。
- 应用隐私、Provider 同意、插件许可及每账户披露分别检查。插件授权不会接受应用隐私政策。
- 歌曲信息旧入口先授权、后启用。注册表提供独立系统授权回调，经 Runtime 检查加载许可、插件许可及应用隐私后调用；无需构造数据客户端，也不会放行禁用状态下的数据请求。MusicKit 继续使用系统授权，HTTP Provider 返回原有已授权状态。
- 未知插件偏好保留；无效 EQ 插件配置留在插件设置中并显示失败，不使整份设置无法载入。

## 两个 EQ / DSP 位置

```mermaid
flowchart LR
    D[各轨解码 PCM] --> P[选定的每轨 DSP]
    P --> R[格式转换]
    R --> M[过渡混音]
    M --> T[变速与已旁路的旧 EQ]
    T --> B[选定的总线 DSP 效果链]
    B --> O[主 mixer 与输出]
```

同一个插件只进入用户选定的位置。正式播放、试听及每轨解码槽拥有独立实例，PCM 处理为零 latency/tail，保留 gapless/crossfade。EQ 维持 32–16000 Hz 十段、±12 dB 和一倍频程带宽；每轨实现使用预分配、分通道的 RBJ 滤波器，在处理循环中不分配、加锁或查询设置，接近/超过 Nyquist 的频段旁路。

总线由单槽改为按 PluginID 稳定排序的串联效果链，EQ 与其他效果可叠加。已挂载的总线 EQ 参数可直接更新节点；新增/移除节点及位置切换仍在暂停/停止后修改音频图。撤权或切换先立即旁路旧实例，每轨参数重配置也在输出停止后挂载。

## 验证

- macOS SwiftPM：HostBridge **30 个测试函数**、Core 设置相关 **20 个测试函数**、独立 EQ **3 个函数 / 6 个执行用例**通过。
- iPhone 17 Pro / iOS 26.5 Simulator：**265 个测试函数 / 290 个执行用例**通过，失败、跳过、预期失败均为 0。包括 App DSP 8 项、持久化及旧 Metadata 开关接入 4 项、UI 200 项、Runtime 23 项、HostBridge 30 项。
- 真实 FFmpeg 输出验证：EQ 每轨/总线各只处理一次；与另一总线效果叠加得到预期增益；生产外部 EQ 模式保持旧引擎 EQ 旁路。旧 Metadata 设置入口完成先系统授权、再启用插件并保存，随后关闭成功。
- 迁移测试覆盖幂等、原 ID/排序、独立应用同意、撤权不恢复、原生账户隔离、目录信息/游标/receipt、授权前不构造数据客户端、迟到结果清理、连续参数编辑和重置。
- 架构检查与 git diff --check 通过。Simulator 命令中的 Core 单函数 selector 未匹配到测试，因此 Core 设置验证采用上述 macOS 20 项结果，不计入 Simulator 数量。
