# 1.3.0 unused VLC adapter removal (2026-09-27)

The App and XcodeGen project already used `FFmpegPlaybackAdapter`; the old
`MusicFreeVLCKitAdapter` package had no production or test-target consumers.
This change removes its 27 tracked files, including the package manifest,
adapter implementation, legacy tests, and duplicate media fixtures. The two
large ALAC fixtures have identical Git object hashes in the FFmpeg adapter's
test resources. The four replacement media fixtures remain available there.

`Scripts/check_architecture.sh` now rejects new VLCKit imports or package
references. The dependency-license model test uses the current FFmpeg manifest
entry. `project.yml` and App composition require no changes.

Verification on the booted iPhone 18 Pro Max simulator (iOS 27.0):

- `MusicFreeUIFeatureTests`: 179 tests passed.
- `MusicFreeFFmpegAdapterTests`: 50 tests passed, including parameterized format
  cases. The combined result has 229 tests, 317 execution items, zero failures,
  and zero skips in `.noindex/artifacts/ffmpeg-no-vlc-adapter-tests.xcresult`.
- After the license fixture update, `MusicFreeUIFeatureTests` passed again:
  179 tests, zero failures or skips in
  `.noindex/artifacts/ffmpeg-no-vlc-license-ui.xcresult`.
- `MusicFreeTests` App host passed 46 tests with zero failures and two expected
  skips: the external fixture corpus is not in the normal test bundle, and
  one diagnostic only applies to Mac Designed for iPad. Result:
  `.noindex/artifacts/ffmpeg-no-vlc-apphost.xcresult`.
- `Scripts/check_architecture.sh` and `git diff --check` passed.
- Generic iOS Release build passed in
  `.noindex/logs/ffmpeg-no-vlc-release-build.log`. Its app bundle contains only
  `FFmpegAudio.framework`; `otool -L` on the main executable shows FFmpeg and
  no VLC linkage.

This source cleanup changes no selected playback engine. The physical
headphone, route-change, interruption, background, and lock-screen acceptance
checks remain open, as does physical-device DS Audio playback.

## Audio-session notification follow-up

An injected `NotificationCenter` now exercises the iOS audio-session bridge
from actual `AVAudioSession` notification names through the active
`AppleAudioSessionManager` event stream. It verifies interruption start/end,
output-route change, and no forwarding after deactivation. The iPhone 18 Pro
Max simulator infrastructure suite passed 231 tests / 242 execution items,
zero failures or skips, in
`.noindex/artifacts/audio-session-notification-final.xcresult`.

This verifies event delivery and lifecycle handling in automation. It does not
show that physical headphones, Bluetooth, or AirPlay produce correct audible
output or route changes on a device.
