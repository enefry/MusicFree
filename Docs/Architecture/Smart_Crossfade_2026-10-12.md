# 智能交叉渐变：首尾分析与自动过渡

## 产品行为

设置 → 播放 → 歌曲过渡 → 交叉淡化，打开“智能交叉渐变”。默认关闭，旧设置缺少 `smartCrossfadeEnabled` 字段时按关闭迁移。智能模式把现有交叉淡化时长作为**上限**，范围 0.1–12 秒；关闭智能模式后，该值用于固定时长渐变。

智能模式在每对歌曲交接前选择上一首开始退场的位置，以及下一首进入的时间和重叠时长。2026-10-15 增加保音高的节拍匹配：可靠拍速接近时，下一首在重叠期间匹配上一首的拍速，再平滑恢复原速；上一首保持原速。仅自动跳过歌曲首尾连续静音，保留曲中停顿。切换至无缝播放或关闭歌曲过渡时，保留智能设置意图，但不运行智能分析；独立静音跳过开关仍按原设置生效。

智能模式生效时，静音开关显示开启并禁用编辑，页脚说明由智能模式自动处理；退出智能模式后恢复用户原来的独立静音设置。

## 分析与规则

| 步骤 | 具体规则 |
| --- | --- |
| 有声边界 | 复用每声道 -80 dB 峰值检测，连续静音至少 250 ms，边缘保留 20 ms；全静音文件保留原内容 |
| 长度确认 | 尾部截断和完整分析只接受实际解码 EOF；容器 duration 仅作 seek 提示。无法确认尾部时回退固定渐变 |
| 响度曲线 | 在源 PCM 上按 10 ms 窗口计算所有声道的 RMS；保留有声边界附近各最多 12 秒的曲线，不保留整首 PCM |
| 起音与节拍 | 检测 RMS 正向突变的局部峰，忽略小于 180 ms 的重复峰；至少 6 个起音、60–180 BPM、至少 80% 的间隔与中位周期相差不超过 40 ms，才接受节拍估计；再选择符合周期网格的最大起音集合，排除孤立的开头起音和尾部窗口边界 |
| 节拍策略 | 两首估计周期相差不超过 6%，才考虑对拍。下一首速度取“下一首周期 / 上一首周期”，第一拍偏移按此速度换算后选取进入点；重叠全程保持匹配拍速。差异低于 0.2% 时保持原速；未启用伸缩的节拍方案仍限制累计漂移不超过 90 ms |
| 速度恢复 | 重叠后在最多 3 秒内按 smoothstep 恢复 1×，开始/结束的速度变化率为零；恢复须在下一首源时间的前半段结束。过短、准备过晚、响度差超过 12 dB 或没有恢复空间时保持原速 |
| 响度策略 | 两首边缘响度差超过 12 dB 时优先 1.5 秒，较响的下一首优先 2 秒，其他情况优先 4 秒；在尾部曲线上搜索能量匹配的进入点，时长偏差参与评分 |
| 时长约束 | 不超过用户设置的上限、任一歌曲有效长度的一半，也不超过上一首尚未输出的长度；准备过晚时缩短过渡 |
| 不可靠分析 | 节拍稀疏、不规则或速度差过大时改用响度策略；未知长度、全静音或分析失败时使用原固定渐变，渲染器继续执行短曲/晚到保护 |

响度是源音频的 RMS 估计，节拍是能量起音的周期估计；这里没有实现 LUFS 标准化、重拍/小节语义识别、调性分析或歌曲结构识别。选择过渡点可以避免较响的交接，但不对整首歌曲做增益补偿。

## 播放链路

`TransitionPreferences.smartCrossfadeEnabled` → `SettingsCoordinator` / `PlaybackCoordinator` 能力裁剪 → `AudioTransitionConfiguration` → `FFmpegPlaybackEngine` → `FFmpegAudioTransitionGraph.Producer`。

- 新能力位 `.smartCrossfade` 只在本地完整歌曲、1 倍速、最多 8 声道且 DSP 保持时序时提供；网络、CUE 分段、变速和改变时序的 DSP 使用现有播放/回退路径。
- Producer 在自己的解码队列完成静音、响度及节拍分析，之后重新 seek 回实际播放起点，再创建原有 `TransitionPCMReader`。扫描每块检查取消。
- 两个槽位各保存一份不可变的 `Sendable` 分析结果；回到 MainActor 时核验 producer ID，防止取消或槽位复用后的旧结果覆盖新曲。
- 下一首先完成分析，等待歌曲对计划，才开始发布 PCM，避免把已缓存的原速音频当作变速后的开头。两个 Producer 各自持有私有 reader 和伸缩器；WSOLA 在各自解码队列中运行，声道共用搜索偏移以保留立体声相位。混音回调仍只读取 PCM、原子状态和既有渐变包络。
- `mft_arm` 使用伸缩后的渲染总帧数；歌曲位置由速度曲线的积分及恢复衔接偏移映射回源时间，累计已播放时长继续使用实际输出帧。恢复结束时选择最后一个相关性匹配的粒窗，从该源位置连续复制到 EOF，保留完整尾部。
- 采用已确认的有声结束位置决定退场；下一首起点取保留 20 ms 的有声边界。进入点由“上一首有声结束位置减重叠时长”确定，节拍策略会补偿下一首稳定网格第一拍距边界的时间。
- 原歌曲进度使用 source offset；播放历史、退场和累计播放时长只计算实际输出帧。自动分析不会把跳过的静音记作已播放内容。
- 切换智能模式、切换过渡风格或改变独立静音设置会失效预加载；必要时重建当前 feeder。修改上限时复用容量足够的缓冲，超过容量才重建。

## 验证范围

本节以下数值为 2026-10-12 第一阶段（保持原速）的验证记录。第二阶段的实现、PCM 对比与真机结果见 [节拍匹配验证](../Testing/Beat_Matching_Validation_2026-10-15.md)。

自动测试覆盖节拍一致/接近/不一致、不规则起音、响度突变、安静进入点、短曲、准备过晚、分析缺失、扫描取消、旧配置迁移、能力裁剪、预加载失效、UIKit 保存和重开。实际音频测试通过 FFmpeg 解码 WAV/ALAC，再进入双路 AVAudioEngine 混音，比较选定重叠与实际 commit/retirement 帧差。

首轮 33 个测试函数通过。14 秒测试音频包含 400 ms 开头静音和 600 ms 结尾静音：节拍一致时选出 4.04 秒重叠，节拍不一致时选出 3.90 秒；上一首 retirement 均为 625918 帧，约 13.04 秒，符合只跳过边缘静音、保留原速有声内容的预期。

完整回归通过 82 个测试函数，0 失败、0 跳过：Core 19、FFmpeg 40、UIKit 23；37 项 C ASan / UBSan 数值测试通过。架构检查及 6 个新增文案的六语言覆盖也通过。修改最终静音状态说明后，另行回归的 2 个设置测试通过。

日志保存在 `.noindex/logs/smart-transition-final-tests.log`、`.noindex/logs/smart-transition-ui-final-tests.log`、`.noindex/logs/smart-transition-render-tests.log` 和 `.noindex/logs/smart-transition-architecture.log`；结果摘要在 `.noindex/artifacts/smart-transition/test-summary.json`，复用 `.noindex/DerivedData/MusicPlayer` 中的 xcresult。

上述编译和 Simulator 验证基于现有开发工作区，包含之前尚未提交的 UIKit 迁移与过渡控制修复。物理设备听测与音乐风格覆盖仍需另行验证，自动数值测试不能代表主观听感验收。

## PCM 存储与音频验证

已增加显式启用的存储节点，在源混音器输出和最终输出两处保存 Float32 WAV。源渲染回调只向预分配的 C SPSC 环形缓冲复制数据；文件写入和 WAV 关闭在独立文件队列完成。默认不记录音频。实时最终输出通过 mixer tap 记录；精确离线验证通过实际 AVAudioEngine render 返回块记录，并在自然结束时排空已预拉取的尾部 PCM。

生成的 WAV/ALAC 对照音频进入真实 FFmpeg 解码与双路混音流程，再从磁盘重读。新增独立验证发现并修复了开头孤立起音误作第一拍，以及离线提前停止截掉 40–80 ms 尾部的问题。固定过渡选出 6.520 秒（短曲一半限制），智能同拍 4.040 秒、异拍 3.900 秒、约 14 dB 音量差场景 1.500 秒。保存音频的同拍过渡拍点差不超过 20 ms，未变速。

完整流程、公开调用接口、证据文件及边界详见 `Docs/Testing/PCM_Transition_Validation_2026-10-12.md`。试听页面和原始 PCM 位于 `.noindex/artifacts/pcm-transition/`。
