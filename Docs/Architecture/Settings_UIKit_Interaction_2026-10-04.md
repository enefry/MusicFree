# UIKit 设置交互调整

按用户提供的截图及 `ScreenRecording_10-05-2026 00-37-47_1.MP4` 调整，页面全部使用 UIKit。

## 行为

1. 应用图标在右侧显示「已选择」和勾选；系统确认切换后更新新旧行。失败保留当前图标选择，显示错误。
2. 强调色进入详情页，提供默认、蓝/绿/紫/黄色及自定义。预置立即应用；自定义选择器内部保留草稿，关闭后保存，避免拖动颜色时整页连续刷新。根页展示当前颜色和色块。
3. 默认播放速度恢复折叠行，右侧显示当前倍速和展开箭头；保存不重置展开状态，滑杆在松手后保存。
4. 均衡器使用竖向频段，普通手机可同时展示全部 10 个频段，较窄屏幕横向滚动。拖动时显示本地数值、松手保存；双击单个频段恢复零增益。「声音风格」菜单提供完整预设目录，右侧显示当前预设或「自定义」，下方两列按钮提供四项快捷预设，另提供恢复平直。关闭均衡器时保留参数和布局。
5. 淡入/淡出、无缝播放、交叉淡化集中到「歌曲过渡」子页。淡入淡出可快速同时设置，也可独立调节；歌曲衔接提供总开关和风格选择，交叉淡化时展示时长。关闭再开启时保留本次页面中编辑的时长。底层支持范围仍为 0–3 秒，不采用示意图的 12 秒范围。
6. 插件根页按音效、歌词、元数据、在线源分组，每个插件仅显示名称、状态和开关摘要。点击进入单插件详情，管理入口、启用能力、加载、许可、配置、DSP 位置或账户来源；隐藏插件可通过顶部开关管理。
7. 插件保存不再统一禁用和降低全页透明度，复用现有单元格、开关和滚动位置。连续偏好操作排队执行。音频分析仅在 DSP 详情订阅，以最多每秒 4 次更新峰值/RMS 单元格，避免每帧重绘整页。

示意图仅作为交互参考，不引入付费锁定，均衡器预设仍使用播放引擎提供的配置。

## 过渡选项无响应的后续修复

保存期间原先会禁用「无缝播放」和「交叉淡化」，UITableView 的选择回调直接丢弃这一阶段的点击。现在两种风格在过渡总开关开启时持续可选，由已有保存队列处理最新选择。此外，设置服务可能在 save 返回前广播提交结果；此前未改变内容的本地回声会被误认为外部修改，取消更新的待保存选择。现统一识别本地提交回声，保留后续编辑。

- 延迟保存测试在修复前失败，修复后通过，确认连续切换最终保存最后一次选择。
- 完整 UI 功能包 216 项测试通过；日志 `.noindex/logs/transition-settings-after.log`。
- 新增设置服务 → 队列 → FFmpeg 真实音频图的集成测试，两种参数用例通过。使用 0.4 秒、330/550 Hz 的本地测试音频，直接检测输出 PCM 中下一首的频率成分：无缝在第 18944 帧进入，100 ms 交叉淡化在第 14848 帧进入，输出采样率 48 kHz，符合 0.4 秒与 0.3 秒的预期边界及分析窗口误差。
- iPhone Simulator 实际点击交叉淡化/无缝各两次，并退出重进，选中互斥和保存结果验证通过；日志 `.noindex/logs/transition-settings-ui-after.log`。

本次没有复现本地正常倍速下的音频过渡失效，也没有修改过渡引擎算法。上述修复针对确定存在的点击丢失和保存竞态；若是自然播完仍听不到效果，需要结合具体曲目、资源类型和倍速继续定位。手动下一首走独立切歌路径，网络资源、CUE 分段及非 1 倍速不适用这些自动衔接效果；文件本身的静音不会被删除。真机问题场景仍待复验。

## 均衡器自定义与预设缺失的后续修复

问题有两部分：当前 FFmpeg 引擎只提供四项预设，旧版古典、摇滚、流行等目录未保留；UIKit 页面也没有展示当前「自定义」状态。现在引擎共提供 21 项预设，保留原四项的 ID 和参数，恢复旧版其余 17 种风格。「声音风格」菜单始终保留全部选项，均衡器开启时，菜单、快捷按钮和恢复平直在保存期间仍可操作。

旧版 VLC 的中心频率和增益范围不同。恢复的曲线在对数频率轴上插值到当前十频段，按 0.5 dB 取整并限制在 ±12 dB；有提升的曲线使用负前级增益预留余量。因此目录恢复不代表与旧 VLC 的听感完全相同。曲线来源和许可证随应用依赖说明打包，不引入 VLCKit 二进制。

实际截图还暴露出切换预设后已拖动频段显示旧值的问题。手势日志确认 UIKit 在 touchUp 后再次发送已取整的 valueChanged，重新打开已提交的本地编辑状态。现在识别该重复值，后续预设刷新能立即更新同一个滑杆。回归测试同时覆盖重复事件后的恢复平直，以及实际拖动后选择古典并在退出页面前检查 1 kHz 为 0 dB。
