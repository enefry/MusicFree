# MusicFree 1.3.0 功能需求：本地播放内核替换为 FFmpeg

目标版本：1.3.0

状态：开发中

基线：1.2.x 已上线的本地播放、导入、探测与元数据链路（VLCKit 实现）

## 1. 版本目标

把本地音乐的播放、媒体探测和元数据读取从 VLCKit 迁移到自有的 FFmpeg 音频链路，降低对 VLC 的依赖，获得可控的解码能力、构建产物和体积。

```text
MusicFreeCore 端口
  PlaybackEngine / PlaybackAudioControlling   MediaProbing   MetadataReading
        |                                          |               |
Packages/MusicFreeFFmpegAdapter（薄适配层）
  FFmpegPlaybackEngine        FFmpegMediaProbe     FFmpegMetadataReader
  （ffmpeg 解码 → AVAudioEngine 输出）
        |
Packages/FFmpegAudioKit（仓库内与业务解耦的 audio-only 封装）
  FFmpegAudioKit (Swift) → CFFmpegAudio (C wrapper) → FFmpegAudio.xcframework
```

- `FFmpegAudioKit` 零业务依赖，只提供解码、探测、元数据三类 API，不含播放器。
- 播放逻辑（投喂、seek、变速、音量、路由变化恢复）留在适配层，不下沉到 SDK。
- ffmpeg 从源码交叉编译（`Packages/FFmpegAudioKit/Scripts/build-ffmpeg.sh`，当前 8.1.2），只启用音频相关组件，打包为动态 framework。仓库内提交 C/Swift 源码与构建脚本；默认二进制由 SDK 清单固定到 `0.0.4` Release，构建产物不入库。只有显式设置 `FFMPEG_AUDIO_USE_LOCAL_BINARY=1` 才使用本地框架，以免本地构建被错误标为正式 Release。

## 2. 版本范围

### 2.1 包含

- 本地文件（`PlaybackResource.localFile`）播放：prepare / play / pause / stop / seek。
- 变速（`AVAudioUnitTimePitch`，保持音高）、软件音量与静音。
- 音频会话路由/硬件格式变化（插拔耳机、蓝牙切换）后从当前位置恢复播放。
- 本地文件媒体探测：容器、时长、音轨列表、采样率、声道、位深、码率、是否含视频。
- 本地文件元数据读取：标题、艺术家、专辑、专辑艺术家、作曲、流派、注释、歌词、曲目号、碟号、年份、时长、内嵌封面。
- App 组装层（`AppContainer`）将主播放引擎、探测器、元数据读取器切换到 FFmpeg 实现。
- 与 VLC 实现一致的事件语义：generation 隔离、`stop()` 后 itemID 置空、播完发出 `.ended`、失败发出 `.failed`。

### 2.2 不包含

- 远程资源探测与元数据读取（在线试听只需播放）。`AppContainer` 已不再使用 VLCKit。
- gapless、crossfade、ReplayGain。
- 视频播放。

### 2.3 移除 VLCKit 的前置条件：FFmpegAudioKit 在线音频播放

在线试听（当前仅 DS Audio 支持）已在 `AppContainer` 中切换到 `FFmpegPlaybackEngine`。ffmpeg 保持 `--disable-network`，使用自定义 `AVIOContext` 和 Swift `URLSession` 处理 HTTP(S) 读取。当前 App 的工程依赖和链接产物已经移除 VLCKit；真实 DS Audio 与真机播放仍待验收。

需要解决：

- **打开与探测**：C 层新增基于读/seek 回调的打开接口；限制 `probesize` / `analyzeduration`，控制起播耗时。
- **请求头**：`RemotePlaybackRequest.headers`（如 `Accept`、`Cookie`）由 URLSession 注入，不进入 ffmpeg，也不写入日志。
- **seek**：服务端支持 `Range` 时用 Range 请求实现 seek；不支持或转码流没有 `Content-Length` 时声明为不可 seek，引擎相应降级 `.seeking` 能力。
- **缓冲**：预读缓冲；数据不足时对外发出 `.buffering` 阶段，恢复后回到 `.playing`，并防止状态抖动。
- **可中断**：网络读取期间 stop、seek、切歌必须能立即打断（`AVIOInterruptCB` + 取消 URLSession 任务），不能卡住解码队列。
- **重连与过期**：短暂断网自动重试；DS Audio 播放地址 5 分钟过期，播放中途需要重新请求时，要能通过回调重新获取 `playbackAccess`。
- **错误映射**：网络错误、401/403、404、超时映射为现有 `PlaybackError` / `OnlineAuditionError`。

进度：`ffaudio_open_io` / `FFmpegByteSource`、适配层 `URLSessionByteSource` 与 `FFmpegPlaybackEngine` 的 `.remote` 支持（Range seek、背压、续传、可中断、缓冲态）已实现并有桩测试；`AppContainer` 已将在线试听切换到 `FFmpegPlaybackEngine`，顺序流（不支持 Range）时 `capabilities` 不含 `.seeking`。过期续签与 401/403 刷新有 HTTP 桩测试，真机与 DS Audio 实测尚未完成；旧适配层源码暂留仓库，不参与 App 构建。

### 2.4 CUE 范围与均衡器

适配层已实现，模拟器自动化测试覆盖逻辑 seek、范围结束、重播以及均衡器参数和校验；真机试听与各格式回归仍须单独验收。

| 标识 | 内容 | 影响 |
| --- | --- | --- |
| `FEATURE(cue-range)` | 支持 `PlaybackSelection.range` 分段播放：起点、seek、进度、时长按 range 换算，PCM 在 `range.end` 截断，最后一帧播放后结束 | 模拟器已测 WAV、AAC/M4A、MP3、FLAC、Ogg/Vorbis seek；M4A 与 FLAC 另测 75 帧/秒 CUE 的亚毫秒起点精度；真机和其余格式待验收 |
| `FEATURE(equalizer)` | 基于 `AVAudioUnitEQ` 的 10 段均衡器，点亮 `.equalizer` 能力位并提供 `equalizerDescriptor` | 模拟器已测配置、参数校验及音频图实际输出变化；真机试听待验收 |

### 2.5 音轨兼容

当前没有音轨选择入口，适配层 README 记录后续接入事项。探测结果的音轨 `stableID` 由 `vlc-media-id:N` 变为 `ffmpeg-stream:N`；后续增加音轨选择时，需决定做映射还是在升级后重新扫描。

## 3. 支持格式

以 `build-ffmpeg.sh` 的组件白名单为准：

- 解码器：AAC（含 LATM）、MP3、FLAC、ALAC、Vorbis、Opus、PCM（s16/s24/s32/f32/u8）、AC-3、E-AC-3、DTS、APE、WavPack、TTA、TAK、Musepack SV7/SV8、Cook、ALS、WMA v1/v2/Lossless/Pro；AAC、MP3、ALAC、AC-3 优先使用 AudioToolbox 硬件解码器。
- 容器：AAC、MP3、FLAC、Ogg、WAV、W64、AIFF、AU、CAF、MOV/M4A、Matroska、APE、ASF、RealMedia、WV、TTA、TAK、DSF、MPC、AC-3、E-AC-3、DTS。RealMedia 已在 `0.0.4` 正式二进制中启用。

新增格式必须同时更新白名单、重新构建 xcframework，并补充对应样本的验收。

## 4. 许可证与分发

- ffmpeg 以 LGPL 配置构建（不启用 `--enable-gpl` / `--enable-nonfree`），静态库整体链接进单个动态 `FFmpegAudio.framework`，App 其余代码可闭源。
- 发布包需在 `ThirdPartyNotices` 中附 ffmpeg 版本、LGPL 许可证文本与源码获取方式。
- 构建脚本、配置参数与所用源码版本须可复现。

## 5. 验收标准

### 5.1 播放

- 各支持格式至少一个样本在真机上可完整播放，时长、进度与实际一致。
- prepare 期间 stop 或切歌，不残留声音、不回写过期状态。
- seek 到开头、中段、接近结尾均正确；接近结尾 seek 不误触发切歌。
- 播完后再次播放从头开始；`stop()` 后再次播放重新 prepare。
- 变速 0.5x–2.0x 音高不变，进度按原始时间轴推进。
- 插拔有线耳机、连接/断开蓝牙、来电中断恢复后，播放位置不回退、不静默。
- 后台播放、锁屏控制、Now Playing 信息与 1.2.x 一致。

### 5.2 探测与元数据

- 导入同一批样本，探测出的时长、音轨、技术信息与 1.2.x 结果一致或更准确。
- 中文、日文及非 UTF-8 标签经 `MetadataTextRepair` 清洗后显示正确。
- 内嵌封面（JPEG/PNG）可正确读取。

### 5.3 回归

- 本地导入、资料库、歌单、队列、睡眠定时、在线试听无回归。
- 构建和测试复用工程 `.noindex/DerivedData`，不创建一次性系统 DerivedData。

## 6. 风险

- **seek 精度**：AAC/M4A、MP3、FLAC 的样本落点已有模拟器回归；C 层通过预热解码与时间戳丢弃目标前 PCM。其它压缩格式、不同编码器产物和真机仍需验收。
- **DSF/DSD**：`0.0.3` Release 二进制已启用四种 DSD 解码器；正式资产在主仓库 SDK、适配层模拟器测试中通过合成 DSF 解码。仍需用真实 DSF 验收。
- **体积**：当前 App 只嵌入 FFmpegAudio.framework；待 Archive 时测量最终安装包体积。
- **测试覆盖**：适配层已有 CUE seek、HTTP 桩和 20 种合成格式样本的模拟器测试；真机 App host 曾完整播放 25 个仓库样本，当前仓库已增至 28 个短样本，新增样本尚未在真机重跑。仍缺部分白名单格式样本、逐格式真机 seek、实际音频输出及真实 DS Audio 验收。
- **无 Range 流路由变化**：模拟器对播放中停滞的顺序流已验证取消旧读取、重开请求、解码至原位置及控制竞态；真实 DS Audio 服务的转码输出是否能稳定重取并定位仍需实测。
- **DS Audio HTTP 端点与 ATS**：在线源配置允许任意 HTTP/HTTPS 端点，App 的 `NSAppTransportSecurity` 目前只声明 `NSAllowsLocalNetworking`。本机 loopback HTTP 已通过真实 URLSession 的 App host 测试；局域网 IP 测试时，主机自己访问其局域网地址上的临时 HTTP 服务也超时，而 `127.0.0.1` 可访问，因此无法从这次失败判断 App 的 ATS 行为（`.noindex/artifacts/ffmpeg-lan-http-preflight.xcresult`）。局域网 NAS 的明文 HTTP 与外网明文 HTTP 仍需分别在可达的真实服务上验证。
