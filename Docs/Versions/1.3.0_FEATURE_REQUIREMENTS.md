# MusicFree 1.3.0 功能需求：本地播放内核替换为 FFmpeg

目标版本：1.3.0

状态：开发中

基线：1.2.x 已上线的本地播放、导入、探测与元数据链路（VLCKit 实现）

## 1. 版本目标

把本地音乐的播放、媒体探测和元数据读取从 VLCKit 迁移到自有的 FFmpeg 音频链路，降低对 VLC 的依赖，获得可控的解码能力、构建产物和体积。

```text
MusicFreeCore 端口
  PlaybackEngine / PlaybackAudioControlling   MediaProbing   MetadataReading
        |                                          |               |
Packages/MusicFreeFFmpegAdapter（薄适配层）
  FFmpegPlaybackEngine        FFmpegMediaProbe     FFmpegMetadataReader
  （ffmpeg 解码 → AVAudioEngine 输出）
        |
thirdpart/FFmpegAudioKit（与业务解耦的 audio-only 封装）
  FFmpegAudioKit (Swift) → CFFmpegAudio (C wrapper) → FFmpegAudio.xcframework
```

- `FFmpegAudioKit` 零业务依赖，只提供解码、探测、元数据三类 API，不含播放器。
- 播放逻辑（投喂、seek、变速、音量、路由变化恢复）留在适配层，不下沉到 SDK。
- ffmpeg 从源码交叉编译（`thirdpart/FFmpegAudioKit/Scripts/build-ffmpeg.sh`，当前 8.1.2），只启用音频相关组件，打包为动态 framework。

## 2. 版本范围

### 2.1 包含

- 本地文件（`PlaybackResource.localFile`）播放：prepare / play / pause / stop / seek。
- 变速（`AVAudioUnitTimePitch`，保持音高）、软件音量与静音。
- 音频会话路由/硬件格式变化（插拔耳机、蓝牙切换）后从当前位置恢复播放。
- 本地文件媒体探测：容器、时长、音轨列表、采样率、声道、位深、码率、是否含视频。
- 本地文件元数据读取：标题、艺术家、专辑、专辑艺术家、作曲、流派、注释、歌词、曲目号、碟号、年份、时长、内嵌封面。
- App 组装层（`AppContainer`）将主播放引擎、探测器、元数据读取器切换到 FFmpeg 实现。
- 与 VLC 实现一致的事件语义：generation 隔离、`stop()` 后 itemID 置空、播完发出 `.ended`、失败发出 `.failed`。

### 2.2 不包含

- 远程资源探测与元数据读取（在线试听只需播放）。VLCKit 在移除前仍随 App 链接，但 `AppContainer` 已不再使用。
- gapless、crossfade、ReplayGain。
- 视频播放。

### 2.3 移除 VLCKit 的前置条件：FFmpegAudioKit 在线音频播放

在线试听（当前仅 DS Audio 支持）仍由 `VLCPlaybackEngine` 承担，由 VLC 负责 HTTP 读取、缓冲、重连和 seek。只有 FFmpegAudioKit 具备在线音频播放能力后，才能移除 VLCKit。

现状：ffmpeg 以 `--disable-network` 构建、只启用 `file` 协议，C 层只能按路径打开本地文件。

推荐方案：不启用 ffmpeg 自带的 http/tls 协议，改用自定义 `AVIOContext`，由 Swift 侧基于 `URLSession` 提供数据。这样可以使用系统 TLS、代理和 ATS 策略，并由原生层控制请求头。

需要解决：

- **打开与探测**：C 层新增基于读/seek 回调的打开接口；限制 `probesize` / `analyzeduration`，控制起播耗时。
- **请求头**：`RemotePlaybackRequest.headers`（如 `Accept`、`Cookie`）由 URLSession 注入，不进入 ffmpeg，也不写入日志。
- **seek**：服务端支持 `Range` 时用 Range 请求实现 seek；不支持或转码流没有 `Content-Length` 时声明为不可 seek，引擎相应降级 `.seeking` 能力。
- **缓冲**：预读缓冲；数据不足时对外发出 `.buffering` 阶段，恢复后回到 `.playing`，并防止状态抖动。
- **可中断**：网络读取期间 stop、seek、切歌必须能立即打断（`AVIOInterruptCB` + 取消 URLSession 任务），不能卡住解码队列。
- **重连与过期**：短暂断网自动重试；DS Audio 播放地址 5 分钟过期，播放中途需要重新请求时，要能通过回调重新获取 `playbackAccess`。
- **错误映射**：网络错误、401/403、404、超时映射为现有 `PlaybackError` / `OnlineAuditionError`。

进度：`ffaudio_open_io` / `FFmpegByteSource`、适配层 `URLSessionByteSource` 与 `FFmpegPlaybackEngine` 的 `.remote` 支持（Range seek、背压、续传、可中断、缓冲态）已实现并有桩测试；`AppContainer` 已将在线试听切换到 `FFmpegPlaybackEngine`，顺序流（不支持 Range）时 `capabilities` 不含 `.seeking`。过期续签（`TODO(remote-refresh)`）、真机与 DS Audio 实测、VLCKit 移除尚未完成。

完成后，`FFmpegPlaybackEngine` 支持 `.remote`，在线试听切换到 FFmpeg 引擎；再移除 `MusicFreeVLCKitAdapter`、VLCKit 依赖及其 `ThirdPartyNotices` 条目。

### 2.4 后续独立 feature（1.3.0 内另行立项）

与 VLC 实现相比的已知差距，不阻塞 FFmpeg 引擎合入，但需在 1.3.0 发布前逐项评估是否补齐：

| 标识 | 内容 | 影响 |
| --- | --- | --- |
| `FEATURE(cue-range)` | 支持 `PlaybackSelection.range` 分段播放：起点、seek、进度、时长按 range 换算，到达 `range.end` 时主动结束 | 未实现前 CUE 分轨会从整轨文件开头播放到文件尾 |
| `FEATURE(equalizer)` | 基于 `AVAudioUnitEQ` 的均衡器，点亮 `.equalizer` 能力位并提供 `equalizerDescriptor` | 未实现前设置页不显示均衡器 |

### 2.5 TODO

- `TODO(audio-stream)`：`PlaybackSelection.audioStream` 尚未透传到解码器，C 层固定使用 `av_find_best_stream` 选轨，多音轨文件忽略用户选择。
- 探测结果的音轨 `stableID` 由 `vlc-media-id:N` 变为 `ffmpeg-stream:N`，已入库曲目的音轨选择无法直接匹配；需决定做映射还是在升级后重新扫描。

## 3. 支持格式

以 `build-ffmpeg.sh` 的组件白名单为准：

- 解码器：AAC（含 LATM）、MP3、FLAC、ALAC、Vorbis、Opus、PCM（s16/s24/s32/f32/u8）、AC-3、E-AC-3、DTS、APE、WavPack、TTA、TAK、Musepack SV7/SV8、Cook、ALS、WMA v1/v2/Lossless/Pro；AAC、MP3、ALAC、AC-3 优先使用 AudioToolbox 硬件解码器。
- 容器：AAC、MP3、FLAC、Ogg、WAV、W64、AIFF、AU、CAF、MOV/M4A、Matroska、APE、ASF、WV、TTA、TAK、DSF、MPC、AC-3、E-AC-3、DTS。

新增格式必须同时更新白名单、重新构建 xcframework，并补充对应样本的验收。

## 4. 许可证与分发

- ffmpeg 以 LGPL 配置构建（不启用 `--enable-gpl` / `--enable-nonfree`），静态库整体链接进单个动态 `FFmpegAudio.framework`，App 其余代码可闭源。
- 发布包需在 `ThirdPartyNotices` 中附 ffmpeg 版本、LGPL 许可证文本与源码获取方式。
- 构建脚本、配置参数与所用源码版本须可复现。

## 5. 验收标准

### 5.1 播放

- 各支持格式至少一个样本在真机上可完整播放，时长、进度与实际一致。
- prepare 期间 stop 或切歌，不残留声音、不回写过期状态。
- seek 到开头、中段、接近结尾均正确；接近结尾 seek 不误触发切歌。
- 播完后再次播放从头开始；`stop()` 后再次播放重新 prepare。
- 变速 0.5x–2.0x 音高不变，进度按原始时间轴推进。
- 插拔有线耳机、连接/断开蓝牙、来电中断恢复后，播放位置不回退、不静默。
- 后台播放、锁屏控制、Now Playing 信息与 1.2.x 一致。

### 5.2 探测与元数据

- 导入同一批样本，探测出的时长、音轨、技术信息与 1.2.x 结果一致或更准确。
- 中文、日文及非 UTF-8 标签经 `MetadataTextRepair` 清洗后显示正确。
- 内嵌封面（JPEG/PNG）可正确读取。

### 5.3 回归

- 本地导入、资料库、歌单、队列、睡眠定时、在线试听无回归。
- 构建和测试复用工程 `.noindex/DerivedData`，不创建一次性系统 DerivedData。

## 6. 风险

- **seek 精度**：当前按关键帧 seek，AAC/M4A 等格式实际落点可能早于目标，进度显示却为目标值。需评估是否按时间戳丢弃多余采样。
- **DSF/DSD**：已启用 DSF 容器但未启用 DSD 解码器，`.dsf` 文件可探测但无法播放。需补解码器或从支持格式中移除。
- **体积**：ffmpeg 动态库叠加仍保留的 VLCKit，1.3.0 包体会增大；彻底移除 VLC 需等远程播放迁移完成。
- **测试覆盖**：适配层目前只有链接冒烟测试，缺少带真实音频样本的集成测试。
