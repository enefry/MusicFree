# MusicFree 1.2.0 功能需求：多媒体源与在线源体系

目标版本：1.2.0

计划分支命名：`1.2.0_feature`

当前开发分支：`feature/1.2.0_dev`

基线：1.1 发布基线 `1b19753`

## 1. 目标

在 1.1 本地音乐播放器能力基础上，引入统一的外部媒体源体系，区分“下载源”和“播放源”，并通过独立的在线源入口管理多个来源实例。

1.2.0 的正式 Provider 范围：

- DS Audio：实现下载源和播放源协议，支持浏览、下载和临时试听。
- Google Drive：实现下载源协议、OAuth、Catalog 浏览、下载并导入本地媒体库。

百度网盘暂不进入 1.2.0 的可用 Provider 范围，只保留后续 Provider 扩展和网关接入边界。

## 2. 版本范围

### 2.1 包含

- 从 1.1 发布基线创建独立开发线；本仓库实际分支为 `feature/1.2.0_dev`，`1.2.0_feature` 为需求原命名。
- 在接入在线源之前完成 App 导航基础改造：iPhone 保留四 Tab，regular width 的 iPad 和 iPad on Mac 使用单一原生三列 UIKit `UISplitViewController(style: .tripleColumn)`。原规划中的 SwiftUI `NavigationSplitView` 仅作为列职责模型保留。
- 消除应用级分栏与资料库/播放列表 Feature 分栏的嵌套，统一一级路由、二级选择和详情路径状态。
- 将移动端主导航调整为四个 Tab：
  1. 资料库
  2. 歌单
  3. 在线源
  4. 设置
- 支持多个在线源实例，包括多个同类型但配置不同的源。
- 在线源列表进入时只打开一个源实例详情页。
- 支持在线源总开关和单个源实例启用/停用。
- 支持应用隐私协议和每个在线源实例独立隐私协议。
- 支持应用协议撤销、源协议单独撤销和缓存离线播放。
- 定义下载源协议和播放源协议。
- DS Audio 浏览、可选搜索、下载、HTTP/转码 URL 试听。
- Google Drive OAuth、Catalog 浏览、下载和本地媒体导入。
- 保持现有本地导入、本地资料库和本地播放链路稳定。

### 2.2 不包含

- 不把 iPhone 底部 Tab 改造成 Sidebar 折叠导航。
- 不使用自绘固定侧栏代替系统 UIKit `UISplitViewController`。
- 百度网盘正式登录、浏览、下载或播放实现。
- DS Audio 完整在线播放队列、后台连续播放、锁屏控制和自动切歌。
- Google Drive 在线试听。
- 在线源远端歌单同步、远端删除、移动、重命名和元数据写回。
- 将远程 URL、Token、Cookie、Header 或播放器对象写入队列、数据库、UserDefaults 或日志。
- 修改 1.1 已冻结的 LogicalTrack、TrackVariant、MediaAsset、CUE 时间语义和本地队列身份。

## 3. 需求一：三列 UIKit 导航基础改造（原规划为 NavigationSplitView）

该需求是 1.2.0 多源 UI 的前置需求。必须先完成导航容器、状态归属和设备适配，再增加“在线源”入口，避免在现有嵌套导航结构上继续叠加 Feature。

本节最初以 SwiftUI `NavigationSplitView` 描述目标职责；由于 1.2.0 已迁移到 UIKit，实际实现以 `UISplitViewController`、`UITabBarController` 和 `UINavigationController` 承载相同的产品行为。

### 3.1 迁移决策与当前结构

原规划的 regular width 容器为 SwiftUI `NavigationSplitView`。当前 UIKit 实现为：

```text
RootViewController
├── compact: RootTabBarController (UITabBarController)
│   ├── UINavigationController + Library
│   ├── UINavigationController + Playlist
│   ├── UINavigationController + Online Sources
│   └── SettingsHostingController (SwiftUI SettingsFeature)
└── regular: UISplitViewController(style: .tripleColumn)
    ├── primary: App Sidebar
    ├── supplementary: 当前路由的列表/目录
    └── secondary: 当前选择的详情
```

UIKit 迁移后的约束与原规划保持一致：

- regular width 下只允许一个根 `UISplitViewController`，Library、Playlist、Online Sources 和 Settings 不得再创建 Feature 级分栏容器。
- Sidebar、列表和详情使用 UIKit 原生列与导航控制器，系统负责列折叠、展开和窗口尺寸变化。
- Settings 目前通过 `SettingsHostingController` 承载既有 SwiftUI SettingsFeature，是 UIKit App Shell 内的兼容层，不改变 App 级路由和返回行为。
- compact 路径保留四 Tab；除 Settings 的 SwiftUI 内容外，资料库、歌单和在线源使用 UIKit 导航控制器。
- UI 测试必须同时覆盖 compact Tab 路由和 regular Sidebar/列路由，不能只依赖 `TabBar`。

### 3.2 目标导航结构

regular width 下全 App 只能存在一个根 `UISplitViewController(style: .tripleColumn)`：

```text
UISplitViewController(style: .tripleColumn)
├── .primary      App Sidebar
├── .supplementary 当前路由的列表/目录
└── .secondary    当前选择的详情
```

三列职责固定：

| 当前路由 | 第一列 Sidebar | 第二列 Content | 第三列 Detail |
| --- | --- | --- | --- |
| 资料库 | App 一级导航 | 歌曲、收藏、播放历史、专辑、艺人、流派、文件夹 | 当前分类内容及歌曲、专辑、艺人等详情 |
| 歌单 | App 一级导航 | 播放列表 | 当前歌单详情 |
| 在线源 | App 一级导航 | 已添加的来源实例 | 来源配置、Catalog 浏览、搜索、试听和下载 |
| 设置 | App 一级导航 | 设置主页或设置分类 | 隐私、存储、关于、播放设置等详情 |

第三列内部允许使用 `UINavigationController` 继续进入深层页面；Feature 在 regular App Shell 中不得再创建 `UISplitViewController`。原 SwiftUI Feature 若继续保留，只能作为 UIKit Hosting 内容，不得重新取得 App 级列容器所有权。

### 3.3 compact 与 regular 产品规则

```text
compact width
└── UITabBarController
    └── 每个 Tab 使用自己的 UINavigationController（Settings 为 UIKit HostingController）

regular width
└── 单一三列 UISplitViewController
```

- iPhone 和 compact width 保留底部 Tab，不改变 1.1 已建立的主要入口和返回行为。
- iPad、Stage Manager 和 iPad on Mac 根据实际 horizontal size class 与系统列折叠行为选择 regular 或 compact App Shell。
- 不使用设备型号或 `userInterfaceIdiom` 硬编码 iPhone/iPad 分支。
- Mini Player 继续作为整个 App Shell 的 bottom safe-area accessory，不归属于单独一列。
- Player Sheet、外观模式和当前播放状态不因列切换重建。

### 3.4 导航状态归属

业务数据状态和导航状态必须分离。建议新增或演进：

```text
AppNavigationState
├── selectedRoute
├── columnVisibility
└── preferredCompactColumn

LibraryNavigationState
├── selectedSection
└── detailPath

PlaylistNavigationState
└── selectedPlaylistID

SettingsNavigationState
└── selectedDestination / detailPath

OnlineSourceNavigationState
├── selectedSourceID
└── browsePath
```

约束：

- `AppRouter` 只管理 App 一级路由和全局 presentation，不直接承载 Provider、下载或播放业务状态。
- Library compact/regular 必须共享同一套规范 selection/path，不能继续维护互不一致的两套路径。
- 切换资料库、歌单、在线源和设置时，默认保留各 route 的选择与详情位置。
- compact 与 regular 相互切换时，当前 route、二级选择和详情必须可恢复。
- 当前选中的歌单、来源或其他对象被删除后，必须清理失效 selection 并显示明确空状态。
- ViewModel 必须由稳定的 Feature Host 持有，不能因列显示/隐藏或 route 切换重复创建和重复加载。

### 3.5 Feature 拆分要求

Feature 从“拥有完整导航容器”调整为“提供 compact scene 和 regular 列内容”：

```text
LibraryFeature
├── LibraryCompactScene
├── LibrarySecondaryColumn
└── LibraryDetailColumn

PlaylistFeature
├── PlaylistCompactScene
├── PlaylistSecondaryColumn
└── PlaylistDetailColumn

SettingsFeature
├── SettingsCompactScene
├── SettingsSecondaryColumn
└── SettingsDetailColumn

OnlineSourceFeature
├── OnlineSourceCompactScene
├── OnlineSourceSecondaryColumn
└── OnlineSourceDetailColumn
```

- 数据加载、导入、收藏、队列和编辑行为继续由现有 Feature ViewModel/Service 负责。
- sheet、alert、文件导入 Picker 和确认框应挂在稳定的 Feature Host 上，避免列切换时重复 presentation。
- 搜索、导入、添加来源等 toolbar item 必须属于对应的第二列或第三列，不能发布到错误的 App 导航列。
- 各列必须拥有稳定 accessibility identifier，供 compact/regular UI 测试共用。

### 3.6 iPhone 影响

预期 iPhone 可见行为保持不变：

- 保留底部四 Tab。
- 保留资料库首页和逐级 push 行为。
- 保留设置页 `NavigationLink` 和系统返回按钮。
- 保留 Mini Player、Player Sheet、播放队列和导入流程。

主要风险：

- iPhone 横屏或尺寸变化时误进入 regular App Shell。
- compact/regular 状态映射后返回路径变化。
- 现有 TabBar UI 测试因路由 helper 调整产生定位回归。

### 3.7 iPad 与 Stage Manager 影响

- 宽横屏允许同时显示三列。
- 竖屏或较窄窗口允许系统折叠 Sidebar/Content，不能强制压缩三列到不可用宽度。
- 用户在 Stage Manager 中连续调整窗口尺寸时，route、selection、详情和滚动上下文不得无故丢失。
- Sidebar 展开/隐藏按钮、标题和 toolbar 使用系统导航行为。
- Library、Playlist、Settings 和 Online Sources 必须共享同一个 regular App Shell。

### 3.8 iPad on Mac 影响与工程配置

iPad on Mac 是该需求的正式验收环境：

- 宽窗口默认使用三列布局。
- 缩窄窗口时使用系统列折叠，不切换为自绘侧栏。
- 标题栏下方不得再出现大片无内容白色区域。
- 支持窗口缩放、鼠标点击、滚轮、键盘焦点和系统 Sidebar toggle。

当前工程生成配置必须统一：

- `project.yml` 是生成源时，`SUPPORTS_MAC_DESIGNED_FOR_IPHONE_IPAD` 必须与生成后的 `MusicFree.xcodeproj` 一致。
- 1.2.0 明确支持 iPad on Mac 后，应将生成源设置为启用并重新生成工程，不允许只手工修改 `.pbxproj`。
- `SUPPORTS_MACCATALYST` 继续为 `false`；本需求不迁移到 Mac Catalyst。

### 3.9 实施顺序

1. 冻结三列职责、compact/regular 产品规则和验收截图。
2. 提取 App、Library、Playlist、Settings 导航状态，不改变现有 UI。
3. 合并 Library compact/regular 路径并增加状态转换测试。
4. 将 Library 拆分为第二列和第三列，接入单一 regular App Shell。
5. 迁移 Playlist 和 Settings，删除 regular 路径中的 Feature 级 `UISplitViewController`；Settings 可暂时保留 UIKit Hosting 兼容层。
6. 增加 Online Sources route 和列占位，再开始在线源业务实现。
7. 统一 iPad on Mac 工程配置、可访问性标识和 UI 测试 helper。
8. 完成 iPhone、iPad、Stage Manager 和 iPad on Mac 验收。

建议按以下独立提交交付：

1. 导航状态提取与单元测试。
2. Library 三列迁移。
3. Playlist/Settings 三列迁移。
4. Online Sources 占位、工程配置和完整回归。

### 3.10 完成标准

- regular App UI 树只有一个根 `UISplitViewController(style: .tripleColumn)`。
- Library、Playlist、Online Sources 和 Settings 在 regular App Shell 中不再创建自己的 `UISplitViewController`。
- iPhone 四 Tab、主要入口和返回行为与 1.1 保持一致。
- iPad 横屏可以显示三列，竖屏和窄窗口可以正常折叠。
- Stage Manager 尺寸变化不丢失当前 route、二级选择和详情。
- iPad on Mac 顶部白色区域消失，窗口缩放和 Sidebar toggle 正常。
- Mini Player、Player Sheet、导入、搜索、设置详情和播放队列无回归。
- `project.yml` 与生成工程的 iPad on Mac 支持设置一致。
- 新增导航状态单元测试及 iPhone/iPad UI 测试，现有 BVT 和 App UI 回归通过。

## 4. 需求二：四 Tab 导航

移动端 Tab 和 iPad 分栏导航保持相同顺序：

1. 资料库：继续承载本地媒体库、远程下载后导入的媒体和现有资料库能力。
2. 歌单：保留现有歌单、收藏和播放列表能力。
3. 在线源：展示和管理已添加的外部媒体源。
4. 设置：管理应用、播放、存储、隐私和在线源全局配置。

### 4.1 在线源列表

- 展示所有已添加的在线源实例。
- 右上角提供“添加源”。
- 支持多个 DS Audio 和多个 Google Drive 配置并存。
- 每个实例使用独立稳定 `MediaSourceID`。
- 点击列表项只进入当前一个源实例的详情页。
- 未实现的 Provider 不显示为可用添加入口。

### 4.2 在线源详情

在线源详情是一个完整的系统导航页面，不再复用设置卡片或自绘返回/刷新控件。根据 Provider 能力展示：

- 系统 `UINavigationController` 标题和返回按钮；不得自绘返回控件。
- 浏览目录；文件夹点击后进入下一级目录，返回由系统导航栈处理。
- 搜索入口，仅在 Provider 声明支持时展示。
- 播放源能力说明和音频行上的“试听”操作。
- 下载源能力说明和音频行上的“导入”操作。
- 当前目录递归导入；导入按钮固定在导航栏右上角。
- 下载进度和失败状态；目录支持系统下拉刷新，不提供刷新工具栏按钮。

来源启用/停用、来源隐私协议查看与撤销、在线源总开关统一放在“设置 > 隐私与联网服务”的独立 section 中。在线源详情只在第一次进入且尚未同意来源协议时弹出协议，不在目录页面长期显示可用性开关或撤销按钮。

### 4.3 在线源下载队列

- 点击“导入”后立即创建独立下载/导入任务。
- 任务由 AppService 生命周期持有，不依赖来源详情页是否仍在显示。
- 离开来源详情、切换 Tab 或通过系统返回后，任务继续执行。
- 在线源列表提供“下载任务”入口，显示进行中、最近完成、取消和失败可重试的任务。
- 任务只保存脱敏状态和来源/对象标识，不保存远程 URL、Token、Cookie、Header 或播放器对象。

## 5. 下载源与播放源协议

### 5.1 在线源实例

每个来源实例必须独立保存：

- `sourceID`
- `providerKind`
- 显示名称
- endpoint 或服务地址
- 凭据引用 ID
- 启用状态
- 来源级隐私协议版本

Provider 类型不能作为来源实例唯一 ID。相同 Provider 的不同账号、不同 NAS 或不同 endpoint 必须可以同时存在。

### 5.2 下载源

下载源必须支持：

- 浏览。
- 下载。
- 可选搜索。

建议协议边界：

```swift
public protocol DownloadSource: OnlineSource {
    func browse(
        _ request: SourceBrowseRequest
    ) async throws -> SourceBrowsePage

    func search(
        _ request: SourceSearchRequest
    ) async throws -> SourceBrowsePage

    func download(
        _ item: SourceMediaItem,
        options: DownloadOptions
    ) async throws -> DownloadReceipt
}
```

约束：

- 浏览和下载是必选能力。
- 搜索通过 capability 声明，未支持时 UI 不显示搜索入口。
- Provider 只返回协议中立的数据和下载结果，不直接写 SwiftData。
- 下载完成后由上层协调器决定是否导入本地媒体库。
- 下载临时文件必须使用安全路径、原子落盘和必要的长度/校验验证。

### 5.3 播放源

播放源扩展下载源：

```swift
public protocol PlaybackSource: DownloadSource {
    func playbackAccess(
        for item: SourceMediaItem,
        purpose: PlaybackPurpose
    ) async throws -> PlaybackAccess
}
```

播放源支持：

- 下载源全部能力。
- 在线音频源数据。
- HTTP 播放地址。
- HTTP 转码 URL。
- VLC HTTP 播放。

播放源必须在 UI 中以独立能力明确呈现，不能只表现为下载源上的一个隐含按钮。详情页应同时展示“下载源”和“播放源（试听）”两项能力；具备播放能力的音频行显示试听操作，不具备播放能力的 Provider 不显示试听入口。

播放 URL 理论上可下载，但不能直接假定播放 URL 一定具备完整下载能力。必须验证响应类型、过期时间、Range、Content-Length 和可重试性；播放资源失效时回退到下载流程。

### 5.4 临时试听

1.2.0 的在线播放只做试听：

- 点击歌曲后通过 VLC HTTP 能力临时播放。
- 不进入正式播放队列。
- 不写入播放历史和播放统计。
- 不承诺后台连续播放、锁屏控制、自动切歌和完整 Now Playing 流程。
- 试听失败时提示原因，必要时引导用户下载后播放。
- 试听期间只保留一个临时在线会话；离开 App 或切换到后台时保留会话、队列和当前位置，不主动停止；来源被停用时停止该会话。

下载完成后统一复用现有本地导入和本地播放链路。

## 6. 隐私协议与在线源可用性

### 6.1 同意条件

首次进入在线源 Tab 时，如果尚未同意应用隐私协议，必须先弹出应用级协议。对单个来源的首次进入，如果尚未同意来源级协议，必须再弹出该来源独立协议。实际访问或操作在线源前必须同时满足：

1. 用户已同意应用隐私协议。
2. 用户已同意当前在线源实例的 Provider 隐私协议。
3. 当前源实例处于启用状态。
4. Provider 凭据有效。

每一个在线源实例单独保存隐私同意。两个不同配置的 DS Audio 源不能共享撤销状态。

在线源可用性和协议撤销只在设置中管理：在线源 Tab 不显示来源级 Toggle 或撤销按钮，避免把“浏览目录”和“修改网络权限”混在同一页面。

### 6.2 应用协议撤销

撤销应用隐私协议时：

- 清除应用级在线同意。
- 撤销所有在线源实例的网络可用性。
- 停止所有在线浏览、搜索、试听和下载请求。
- 保留源配置、资料库记录、歌单、收藏和历史。
- 已完成的本地缓存仍允许离线播放。
- 重新同意应用协议后，所有在线源仍需分别重新同意源级协议。

### 6.3 单源协议撤销

撤销某个在线源协议时：

- 立即停止该源的浏览、搜索、试听和下载。
- 保留来源配置和已导入的媒体记录。
- 已完成缓存允许继续离线播放。
- 其他在线源不受影响。

### 6.4 在线源总开关

- 设置中提供“在线源”总开关。
- 关闭时禁止新的网络请求，但不删除来源、凭据或缓存。
- 重新打开后，仅恢复满足隐私同意和源实例启用条件的来源。

## 7. DS Audio

新增 `DSAudioAdapter`，同时实现 `DownloadSource` 和 `PlaybackSource`。

### 7.1 功能

- DSM/Audio Station 连接。
- DSM Session 登录、刷新和退出。
- 目录浏览。
- 专辑、艺人、歌曲和封面数据。
- 可选搜索。
- 音频下载。
- 在线音频 URL。
- HTTP 转码 URL。
- VLC HTTP 临时试听。
- Session 过期后的受控刷新。
- 限流、超时、权限、资源不存在和格式错误映射。

### 7.2 数据流

```text
DS Audio
  -> DSAudioAdapter
  -> Browse / Search / PlaybackAccess / Download
  -> OnlineSourceCoordinator
  -> 临时试听或 DownloadReceipt
  -> LocalMediaImporter
  -> 现有本地资料库和播放器
```

### 7.3 首版限制

- 只读，不实现远端歌单、删除、移动、重命名和元数据回写。
- 不实现完整在线播放队列。
- 不把未经真实 DSM 验证的 CUE、Sidecar 或转码行为写成已支持能力。
- 第三方 `synology-api` 仅作为协议参考，不作为 iOS 运行时依赖。

## 8. Google Drive

新增 `GoogleDriveAdapter`，实现 `DownloadSource`，不实现 `PlaybackSource`。

### 8.1 功能

- Provider 类型注册。
- OAuth 登录和 Token refresh。
- 多账号来源实例。
- Catalog 文件夹浏览。
- 音频文件元数据读取。
- 音频文件下载。
- 下载取消、失败和重试。
- 下载后导入本地媒体库。

搜索能力在协议中保留为可选能力；本阶段不作为 Google Drive 首次闭环的阻塞项。

### 8.2 固定导入策略

Google Drive 下载后进入现有本地导入链路：

```text
Google Drive
  -> GoogleDriveAdapter.download
  -> DownloadReceipt
  -> LocalMediaImporter
  -> Managed Media
  -> 现有 Library / Playback
```

下载完成后媒体归属本地托管媒体，Google Drive 不作为后续播放 Variant 保存。本阶段不实现 Google Drive 在线试听。

## 10. 服务与持久化

新增或演进以下服务：

- `OnlineSourceManager`
- `OnlineSourceConfigurationRepository`
- `OnlineSourcePrivacyCoordinator`
- `DownloadSourceCoordinator`
- `OnlineAuditionCoordinator`
- `CredentialVault`
- `DownloadImportCoordinator`

持久化内容：

- 来源实例配置。
- Provider 类型。
- 来源启用状态。
- Credential record ID。
- 来源级隐私协议版本。

禁止持久化：

- DSM SID、Cookie 和密码。
- 临时播放 URL、下载 URL 和转码 URL。
- HTTP Header。
- VLC 对象。
- 包含敏感参数的完整远程路径。

单个来源连接失败不得阻塞本地资料库、现有播放和其他来源。
