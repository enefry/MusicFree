# MusicFree 1.1.0 功能需求：MusicKit 元数据补充

> 原文件名：`1.1_Lyrics_Feature.md`。根据已确认的技术边界，本版本不接入 Apple Music 歌词正文；现有本地歌词能力保持不变。

## 1. 目标

在本地音频导入后，使用 MusicKit 的 Apple Music catalog 能力补充缺失的歌曲元数据和封面。该能力必须是可选的、可取消的、可重试的，并且不能影响本地导入、离线播放和资料库首次加载。

目标版本：1.1.0

目标 checkout：`MusicFree` main

## 2. 范围

### 2.1 本次包含

- 设置页增加“使用 MusicKit 补充元数据”开关，默认关闭。
- 开关开启后请求 MusicKit 授权。
- 设置页增加“扫描并补充”操作，扫描已有本地歌曲。
- 新导入歌曲在本地事务成功后异步补充元数据。
- 文件缺少有效标签时，使用文件名去扩展名作为查询条件。
- 支持标题、艺人、专辑艺人、专辑、流派、年份、曲号、碟号和封面。
- 只补充空字段；已有非空字段、用户编辑内容、收藏和播放统计不被覆盖。
- 增加 `MetadataEnrichmentRecord`，记录查询指纹、catalog ID、状态、重试和已更新字段。
- 搜索和封面下载受并发限制、缓存、退避和 `Retry-After` 约束。

### 2.2 明确不包含

- 不接入 Apple Music 歌词 API。
- 不把 Apple Music developer token、私钥或歌词服务端引入 App。
- 不把音频文件、绝对路径或原始本地标签上传给第三方服务。
- 不写回原始音频文件的 ID3/MP4 等标签。
- 不替换已有元数据，不做用户候选选择页。
- 不改变现有内嵌歌词、`.lrc` 伴随文件和歌词播放器 UI。

## 3. 产品规则

### 3.1 开关

- `useMusicKitMetadataEnrichment` 持久化在 `ImportPreferences`，默认 `false`。
- 开关关闭时不发起 MusicKit 请求，也不启动导入后补充任务。
- 开启动作触发 `MusicAuthorization.request()`；拒绝、限制或不可用时保持关闭并展示原因。
- 关闭开关时取消排队任务；已完成的元数据不回滚。
- 设置重置后恢复关闭状态。

### 3.2 导入后补充

1. 先执行现有本地导入：复制、hash、probe、本地标签读取、封面写入和资料库事务。
2. 本地事务成功后再排队 enrichment，不阻塞导入终态。
3. 新任务只处理本地资料库中的歌曲；失败只记录 enrichment 失败，不改变导入结果。
4. 导入流消费结束或界面离开不能导致已提交歌曲丢失；补充任务由 AppServices 持有。

### 3.3 查询条件

- 有有效标题时优先使用“标题 + 艺人”，其次使用“标题 + 专辑”。
- 标题等于文件名去扩展名时，视为 filename fallback，可用 MusicKit 返回的标题替换。
- 缺少有效标签时使用文件名查询。
- 文件名清理序号前缀、扩展名和明显的括号标签，并支持 `艺人 - 歌曲名`。

### 3.4 匹配和写入

- 候选按标题、艺人、专辑、时长、曲号和年份评分。
- 第一名必须达到阈值，且与第二名有足够差距；不确定时不自动写入。
- 仅将 MusicKit 结果映射到当前为空的字段。
- 仅当本地标题是 filename fallback 时才允许替换标题。
- 仅当本地没有封面时下载并持久化封面。
- 每首歌使用一个原子 metadata update，失败时不产生部分可见更新。

## 4. `MetadataEnrichmentRecord`

`MetadataEnrichmentRecord` 是独立的 Codable 持久化记录，放在 LibraryPersistenceAdapter 的状态文件中，不改变现有 SwiftData library schema。

建议字段：

| 字段 | 说明 |
| --- | --- |
| `itemID` | 本地歌曲稳定 ID，唯一键 |
| `provider` | 当前为 `musicKit` |
| `queryFingerprint` | 清理后的查询和缺失字段指纹，不保存原始路径 |
| `catalogID` | 成功匹配的 MusicKit catalog ID |
| `candidateCount` | 最近一次搜索返回的可用候选数量，不保存候选内容 |
| `status` | queued、running、matched、noMatch、ambiguous、rateLimited、failed、cancelled |
| `attemptCount` | 自动尝试次数 |
| `lastAttemptAt` | 最近尝试时间 |
| `nextRetryAt` | 允许再次自动尝试的时间 |
| `updatedFields` | 本次已经补充的字段集合 |
| `lastErrorCode` | 脱敏后的稳定错误码 |
| `lastHTTPStatus` | 可选 HTTP 状态，不保存响应正文 |

记录不保存 token、私钥、歌词、音频数据、原始 URL 或完整 Apple Music 响应。

入口：设置页“导入与资料库” section。

### 5.1 默认状态

- Toggle：`使用 MusicKit 补充元数据`，默认关闭。

- 扫描中：显示进度、当前状态和取消按钮。
- 扫描完成：显示匹配、无匹配、不确定、失败数量。
- 所有按钮提供稳定 accessibility identifier：
  - `settings.import.musicKitEnrichment`
  - `settings.import.musicKitScan`
  - `settings.import.musicKitCancel`
  - `settings.import.musicKitProgress`

### 5.3 文案边界

UI 只说明“补充元数据和封面”，不显示“自动补充歌词”。本地已有歌词入口和歌词页面文案不改。

## 7. 限流和重试策略

- 应用内 catalog 工作单并发为 1；扫描按页读取，单首处理完成后再推进，避免突发请求。
- 每首歌曲一次搜索最多返回 10 个候选；成功匹配后只在缺少封面时发起一次封面下载。
- 收到 429 时读取数值型 `Retry-After`，没有该值时使用指数退避；单次等待和持久化下次重试时间均有上限。
- 自动最多尝试 3 次，失败写入 `MetadataEnrichmentRecord`，取消、离线、授权失败不会阻断导入。
- 已匹配且查询指纹未变化的歌曲不重复请求。
- 离线、授权失败和无匹配都必须成为可见但不阻断导入的状态。

Apple 没有为本功能所使用的 MusicKit catalog 公共接口承诺一个固定的“每个 App 每天 N 次”额度；实际限制可能按账号、地区、服务状态和请求行为变化，并以服务端响应为准。实现不使用 Apple Music developer token，采用单并发、指纹去重、最多 3 次自动尝试和 `429`/`Retry-After` 处理控制调用量。

## 8. 验收标准

- 开关关闭时，导入和扫描没有 MusicKit 请求。
- 开关开启且授权成功时，缺失元数据的歌曲可以被补充。
- 文件名 fallback 可以匹配并替换本地默认标题。
- 已有标题、艺人、专辑、封面、收藏和播放统计不被覆盖。
- 无网络、拒绝授权、429、无匹配和不确定候选均不会造成导入失败。
- 扫描可取消，已完成结果保留，再次扫描可依据记录继续。
- `MetadataEnrichmentRecord` 可跨启动恢复，且不包含敏感凭据和原始路径。
- 现有本地歌词导入和播放器歌词展示回归测试继续通过。
