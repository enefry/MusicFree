## 2. 范围与边界

插件主项本版包含歌词、歌曲信息、在线源、DSP 四类扩展点，提供通用契约、Runtime、宿主桥和参考实现。插件随 App 编译，支持可选注册和按需实例化；远程可执行插件/插件商店不在范围。播放器 UI 插件待后续讨论，本版不提供接口、占位协议或实现。

本版原有歌词、元数据和在线源保持正常工作，播放引擎、UIKit 播放器及 Coordinator 继续由宿主管理。既有歌词 Provider 与在线源 adapter 后续拆离为插件，列入 roadmap；本版兼容路径不是永久限制。MusicLyricsAPI 暂不查找、恢复、接入、迁移或验收，不作为开发前置条件。公开宿主继续无私有包依赖，显示、启用、允许加载与联网许可分别定义。

平滑播放区分 fade、gapless 与 crossfade 三个行为；设置项和能力位存在不等于功能已实现。已有音量、静音、EQ、速度、CUE、播放历史、歌词和系统 Now Playing 行为作为回归基线。

淡入、淡出和 crossfade 分别支持用户调整 0-3 s，0 为关闭，3 s 同时是偏好/API 和实际调度上限；gapless 单独启停。旧 crossfade 超过 3 s 的合法值迁移为 3 s，旧关闭值保持关闭。修改时长/关闭的取消、在途切换和持久化列入验收。

两项不进入 1.3 的功能范围。当前 `basic_config.xcconfig` 仍为 `1.3.2 / 2026100102`，本轮遵循只做 plan 的要求保留现状；正式开发启动时再同步 1.4 的构建身份。

### 2.1 审核时重点确认的新增设计

| 项目 | 推荐提案 | 确认后影响 |
| --- | --- | --- |
| A：依赖边界 | 基础 API/Runtime 零业务依赖，专用音频契约和宿主桥分离 | 数据插件无需 Core/UI，本版不创建 UIKit 插件契约 |
| A：在线源开放 | 封闭 Provider enum 迁移为兼容旧 raw value 的注册 ID | 保留账户、SourceID、凭据引用和下载恢复记录，支持多账户/仅播放/仅下载 |
| A：开关默认 | 新参考插件可显示，但默认不启用/加载；显示与能力运行独立 | 不自动授予联网，MusicLyricsAPI 不处理，既有服务暂不拆离 |
| B：普通播放控制 | 可调淡入/淡出各 0-3 s；新安装建议 80/120 ms，旧设置新增 fade 为 0 | 普通暂停/停止按用户时长软 fade，紧急情况立即硬停止 |
| B：自动切歌 | 可调 crossfade 0-3 s；默认关闭，首次明确开启建议 1 s；gapless 独立 | 旧 0-3 s 值保留，超过 3 s 迁移为 3 s，关闭值不自动开启 |
| B：逻辑当前歌曲 | 下一轨首个有效输出帧提交，保留音源自然静音 | 歌词、Now Playing、历史与队列共享同一逻辑当前曲目 |
| B：首个原型与降级 | 从 rate=1/可靠共同输出格式开始，在线试听先只支持单曲 fade | 不支持的组合诚实降级；不同格式/速度与防削波策略根据原型裁决 |

两项独立并行、确认后才开发、本版暂缓 UI 插件接口/实现和 MusicLyricsAPI、歌词/在线源后续拆离、时长可关闭且最长 3 s 已由用户明确。上表的具体默认值、接口结构和首个原型限制仍是提案；是否将格式/速度限制延续为发布范围，需要原型后明确决定。

### 2.1.1 2026-10-12 歌曲过渡扩展

用户已明确要求将交叉渐变上限从 3 秒提高到 12 秒，并增加静音跳过能力。该要求取代上表关于 crossfade 最长 3 秒的约束；独立淡入/淡出仍为 0–3 秒。

- Crossfade 设置、持久化、效果契约和实际预读窗口统一支持 0–12 秒；短歌曲仍限制重叠不超过任一歌曲可播放长度的一半。
- 新增独立的“跳过首尾静音”开关，默认关闭，关闭歌曲过渡不会关闭此开关。已有设置缺少该字段时按关闭迁移。
- 本地完整歌曲在 1 倍速、音频处理保持时序时，检测各声道原始 PCM，跳过至少 250 ms 的连续首尾静音；保留曲中停顿和边缘各 20 ms。网络播放、CUE 分段、变速等不支持组合保留原播放行为。
- 采用保守的 -80 dB 峰值阈值；全静音文件保留原播放。音乐进度仍使用原歌曲时间轴，过渡退场的已播放时长排除跳过的开头。
- 解码队列负责检测与变换，音频渲染回调只读取 PCM 和原子状态；预读内存按所选过渡时长分配，静音检测可取消。

### 2.2 后续 roadmap

- 既有歌词 Provider 拆为插件，保留本地优先、身份、顺序、缓存和隐私同意。
- 既有在线源 adapter/配置/注册拆为插件，保留账户、凭据引用、SourceID、授权、访问刷新与下载恢复。
- MusicLyricsAPI 后续单独决定处理计划，本版无恢复或接入任务。
- 播放器 UI 插件先讨论主题/组件/完整布局/MiniPlayer 的产品方案，再设计接口；本版不预留实现或接口。

## 3. 并行职责与合流规则

| 文件或模块 | 主责 | 并行约束 |
| --- | --- | --- |
| 新插件 API、Runtime、宿主桥与插件设置 | A | 不要求 B 引入 Runtime；不修改播放切换状态机 |
| PlaybackAPI 过渡契约、Coordinator、解码投喂与轨道调度 | B | 保留既有效果与播放端口，不要求 A 先实现插件 |
| FFmpeg 音频图 / 效果挂载点 | B 负责播放图拓扑；A 提供 DSP 挂载契约 | A 的 DSP 对接单独小补丁，由 B 核对拓扑；不由两条支线同时重写连接函数 |
| PlayerFeature 的过渡设置/状态展示 | B | 与 A 划分具体文件/函数后接入；先确保默认 UI 可用 |
| AppContainer、RootViewController、Settings 挂载、Package.swift、project.yml | 合流负责人 | 两条支线提交集成需求清单；按顺序组装，不并发改同一文件 |
| AppSettings schema、SettingsMigration、SettingsCoordinator 的共享映射 | 合流负责人 | A 提供插件字段，B 提供 fade 字段；合并版本化 decode/迁移，不各自增加冲突 schema |
| 版本、公共索引、验收汇总 | 合流负责人 | 按各支线实际证据更新，不提前写成已完成 |

开发前逐项确定写入范围。共享文件一次只由一方修改；另一方通过明确的接口变更清单提出需求。不得在共享工作目录执行 `git reset`、`git clean`、批量恢复或宽泛暂存，不覆盖现有未跟踪 `thirdpart/` 内容。

同一 checkout 的 Xcode 构建/测试串行，避免并行锁争用。复用主仓库 `.noindex/DerivedData`；独立 SwiftPM 验证使用各支线固定 scratch 子目录，日志和可清理工件放 `.noindex/`。将来如用户要求新 worktree，再采用有限、可识别的 worktree 专用 DerivedData。

## 4. 确认门槛与开发次序

本次两条子代理支线只负责源码核对和详细计划。主任务核对独立性、共享文件职责、相对链接和源码证据，形成可审核结果；不运行产品构建或测试，也不声明功能实现或通过验收。

用户确认可按支线分别给出；只确认 A 则只启动 A，只确认 B 则只启动 B，同时确认才同时启动。计划中的“推荐”默认值是提案，不是当前产品行为，也不替代用户确认。

确认内容：功能范围、模块边界、阶段次序、建议默认策略、验收条件及详细计划中的需要裁决事项。若批准后发现范围扩大或用户可见策略明显变化，先更新方案再请用户确认该变化；日常实现细节在已批准边界内推进。

计划批准后，A 从四类通用契约/Runtime 与参考插件闭环推进，B 从增益包络/下一首预准备与实际输出原型推进。两条支线各自阶段验收再合流，不等待对方整项完成。公开构建、插件旁路与过渡组合、既有歌词/在线源/默认播放器回归列入集成验收；延期项不成为门槛。

## 5. 验证状态与完成定义

### 5.1 独立与组合验收

| 组合 | 必须满足的结果 |
| --- | --- |
| 仅 A；B 未实现或关闭 | 四类通用能力与参考接入可各自验证，DSP 接当前单轨，既有服务正常 |
| 仅 B；无 PluginRuntime 或私有仓库 | 本地 fade/gapless/crossfade 可验证，默认播放器与既有源不依赖插件 |
| A + B；全部插件关闭 | 基础播放与过渡、既有歌词和在线源正常，没有多余插件实例 |
| A + B；DSP 启用/旁路 | 每轨与混音后作用域、增益、延迟、reset/tail 和图重连行为一致 |
| A + B；使用现有播放器 UI | 快速切歌、时长调整/关闭、歌词、进度、队列与系统 Now Playing 一致；不接入 UI 插件 |
| A + B；在线源账户撤销或联网许可撤回 | 取消受影响任务与预备轨道，硬停止策略有效，迟到结果不重新写库或恢复声音 |
| 公开构建 | 四类通用插件与过渡可生成/构建/验证，无 MusicLyricsAPI 必选依赖 |
| 过渡时长设置与迁移 | 三项 0/正常值/3 s、关闭/重启持久化/运行中修改通过；历史超限值迁移、当前超限输入拒绝，实际窗口最长 3 s |

每条支线内部的数值、生命周期、迁移和用户交互验收详见各自计划。合流不以“两个单独测试均通过”替代上述组合验证。
